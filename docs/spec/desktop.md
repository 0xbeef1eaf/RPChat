# @rp/desktop — Electron application

Depends on: every package. Built with electron-vite 5 (three entries: `src/main`, `src/preload`, `src/renderer`). React 19, TypeScript. No UI library (hand-written CSS with CSS variables; light/dark via `prefers-color-scheme` and the `theme` setting). No native modules.

## Main process (`src/main/`)

- `index.ts`: app lifecycle; single instance lock; creates `MainWindow`; registers `rp-asset://` protocol (`protocol.handle`) that serves files **only** from installed pack roots (look up pack root via engine.packs; resolve with `@rp/pack` `resolveAssetPath`; correct `Content-Type`; support `Range` requests for video/audio — implement a range-aware response using `fs.createReadStream` → `Response` with `206`).
- `engine.ts`: builds `Engine` with `FileStorage(app.getPath('userData')/data)`, `packsDir`, `createStandardRegistry()`, `QuickJsRunner`, `createProvider`, host handlers below, a `permissionPrompter` that opens a prompt window for the request and awaits `permissions:respond`, `appVersion`.
- Unprompted messages: `[self-wake]` system notes (what `sdk.llm.wake` hands the model) are hidden in the chat view and timer-origin replies carry no badge, so a wake reads as the character speaking first; the main process shows a desktop notification titled with the character's name (turn replies once the turn finishes, behaviour `chat.say` messages when added) unless the user is watching that very conversation — the renderer reports it with `app.setVisibleSession(sessionId | null)` whenever the route or active session changes, so a message arriving while Settings is open is announced even though the window is focused. Clicking the notification brings the window back and opens that session (`app:showSession` → `app.onShowSession`). The turn itself never depends on any of this: the engine runs wakes, timers and events whatever the app is showing.
- Session state: `sessions.resetState(sessionId)` (Session settings → *Reset session state*, confirm) forgets scratch state, timers, subscriptions, summary and status; messages stay. Characters have one chat each: the sidebar › and pack card *Chat* buttons open the existing session.
- History editing: `sessions.removeMessage(sessionId, messageId)` and `sessions.clearMessages(sessionId)` (both abort a running turn first and emit `message-removed` / `messages-cleared` chat events; the session, its state, timers and memories stay). Chat header: **Clear history** (confirm); each message shows a delete button on hover.
- Retry: `chat.retry(sessionId)` aborts a running turn, deletes the run of assistant messages at the end of the transcript (`trailingReply`) and runs the turn again over what is left, so the character answers the same user message or `[self-wake]` note afresh. With no reply to drop (the turn errored) it just runs the turn. It refuses (`INVALID_ARGUMENT`) when the transcript is all assistant messages — a session showing only its greeting has nothing to answer. Side effects of the discarded reply (media, memories, timers) are not undone. In the UI: a `↻` next to the newest reply's delete button, and a **Try again** button in the error callout.
- `ipc.ts`: implements every `IpcApi` method as `ipcMain.handle('<ns>:<method>', …)`; forwards `engine.events` `chat` → `webContents.send('chat:event', ev)` to the main window; validates `sender` (only our windows). `browser.*`: `status`, `setPort` (saves the setting and rebinds the loopback server), `trust`/`untrust` (settings + live connection), `installPolicy`/`removePolicy` (`SystemIntegration.installBrowserPolicy` / `removeBrowserPolicy` run `install.sh --browser-only …` / `--remove-browser-policy` with pkexec; `--browser-home <url>` from `settings.browser.homePage` and repeatable `--browser-policy-dir <dir>` from `settings.browser.extraPolicyDirs`), `extensionDir`, `blocks` / `clearBlocks` (`rules.list` / `rules.clear` on the connected extension), `setHomePage` (saves `settings.browser.homePage` and pushes `home.set`); bridge status changes are pushed on `browser:status`.
- `capabilities/media.ts`: `CapabilityHandler` for `media`: manages `MediaWindow` instances (one frameless, transparent, `alwaysOnTop` per settings, positioned per `MediaPosition` on the primary display's work area; reuse one window per position; audio uses a hidden window). Sends `MediaCommand` over IPC with `assetUrl(packId, path)`; tracks `MediaItem`s; `close`, `closeAll`, `list`; auto-close on `ended`/`durationMs`; window close → item removed.
- `capabilities/ui.ts`: `notify` via `Notification`, with an urgency the character chooses (`sdk.ui.notify(title, body, { urgency })`: `low` silent, `normal` the default, `critical` `timeoutType: 'never'`; anything unknown is `normal`); `confirm`/`choose`/`ask` → a prompt window per question (see *Prompt windows* below).
- `loopback.ts`: the `LoopbackServer` on `127.0.0.1` is always started. It binds `settings.browser.bridgePort` (default 47821; env `RP_BROWSER_BRIDGE_PORT` overrides it for tests) and falls back to an ephemeral port with a logged warning when that is taken (`listeningPort`, `requestedPort`, `portFallback`; `rebind(port)` for the settings change). Besides the token-guarded media pages and assets it serves token-less routes registered with `route(prefix, handler)` and hands WebSocket upgrades to `onUpgrade` handlers.
- `browser/` (docs/browser-extension.md): `extension.ts` (`ExtensionService`: locates `resources/extension`, owns `<userData>/extension-key.pem`, packs the CRX once per manifest version, serves `GET /extension/update.xml` (Omaha), `/extension/rp-code.crx`, `/extension/id`), `crx.ts` (hand-written CRX3 + protobuf, deterministic `fflate` zip, Chrome-style id derivation), `policy.ts` (pure: the Chromium policy JSON, the update XML, the Linux policy directories) and `bridge.ts` (`BrowserBridge`: accepts `/bridge` upgrades only from `chrome-extension://<id>` origins, waits 5 s for `hello`, asks the user once per id through `uiPrompts` (a `confirm` prompt window; smoke mode auto-trusts), remembers ids in `settings.browser.trustedExtensionIds`, keeps one live connection per id (newest wins), `request(op, args)` with a 15 s timeout, `onEvent`, `onStatus`, `status()`). `tab-updated` events with `status: 'complete'` are pushed into the senses provider as the `browser-navigated` host event. The `browser` capability handler routes every method but `open` through the bridge and applies `settings.web.allowlist` to every URL it opens, navigates to, bookmarks, redirects to or sets as home page. The 2.1 methods (`block/unblock/blocks/clearBlocks`, `imageEffect/clearImageEffects`, `setHomePage/homePage`, `bookmarks/searchBookmarks/addBookmark/removeBookmark`, `eval`, `history/historyVisits/recentHistory`) read `settings.browser` for the toggles (`allowBlocking`, `allowEval`, `allowHistory` → `CAPABILITY_FAILED` naming Settings → Browser), refuse block patterns for 127.0.0.1/localhost/browser schemes, name the acting character on the extension's blocked page, resolve `replaceWith` pack assets to the loopback asset URL (`loopback.rewriteAssetUrl(assetUrl(pack, asset))`), and stretch the bridge request timeout for `eval`. The engine pushes `settings.browser.homePage` to the extension (`home.set`) whenever one connects.
- `capabilities/system.ts`: `openExternal` (http/https only via `shell.openExternal`), `exec` (`child_process.spawn`, no shell, timeout default 30 s, output capped 64 KiB), `readFile`/`writeFile` (absolute path required; cap 1 MiB), `clipboardWrite`. All permission gating is done by core's dispatcher (level `prompt`); these handlers just execute.
- `windows.ts`: `createMainWindow`, `openPromptWindow(payload)` / `closePromptWindow(id)`, `createMediaWindow(position)`; `webPreferences: { preload, contextIsolation: true, sandbox: true, nodeIntegration: false }`; CSP header via `session.defaultSession.webRequest.onHeadersReceived` (`default-src 'self' rp-asset:; media-src rp-asset:; img-src rp-asset: data:; style-src 'self' 'unsafe-inline'`).
- `dev-mode`: if env `RP_MOCK_LLM=1`, `providerFactory` returns a `MockProvider` that answers with a scripted `run_action` showing an image then text, so the app can be exercised without an API key. With `RP_SMOKE_BROWSER=1` on top of `RP_SMOKE=1` the run instead executes `runBrowserSmoke`: it serves `/smoke/page.html` and `/smoke/page2.html` on the loopback server, logs `[smoke] browser bridge listening on port N` (the smoke script launches Chromium with the unpacked extension on that port), waits for the extension, installs a generated pack with the `browser` capability and sends `browse <url>`, which the mock model answers with a turn exercising `sdk.browser` (status, openTab, read, query, find, type, scroll, screenshot, click, tabs) plus an `sdk.events.on('browser-navigated')` handler; `[smoke] verify browser: PASS|FAIL` reports it. A second message, `exercise <smoke url> <blocked url> <home url>`, runs the 2.1 capabilities (block `smoke.test/smoke/page2*` and open it — the launcher maps `smoke.test` onto 127.0.0.1 —, unblock, `grayscale` + pack-asset `replaceWith` read back through `eval`, `setHomePage` (the launcher then opens `chrome://newtab`; the app waits for the `browser-navigated` event on `/smoke/home.html`), add/search/list/remove a bookmark, `eval` in both worlds, history); `[smoke] verify browser capabilities: PASS|FAIL` lists each, and `[smoke] browser smoke done` ends the run. Under `RP_SMOKE=1` a second turn (the message "ask me something") runs `sdk.ui.confirm`, and `verifyPromptWindow` waits for the prompt window to be on screen, screenshots it, clicks *Yes* in it and checks the answer reached the action (`[smoke] verify prompt: PASS`). It runs **after** `captureWindows`: the first turn's image closes itself 20 s after it is shown, so the media checks must not wait behind it. `[smoke] smoke done` marks the end of the run — both smoke scripts grab the framebuffer on `screenshots done` and only then wait for it.
- `updates/service.ts`: `UpdateService` around `electron-updater`'s `autoUpdater` (injected as `UpdaterLike`, so tests use a fake emitter). Feed: the private GitHub releases of this repository (`build.publish` in `package.json` makes electron-builder emit `latest-linux.yml`; the release workflow attaches it). Per-user GitHub token in `<userData>/update-token.bin`, encrypted with `safeStorage` (plaintext `0600` fallback with a warning), never in settings or logs. Packaging detection: `APPIMAGE` env → `appimage` (in-place install only when the file and its directory are writable), `execPath` under `/opt` or `/usr` → `deb` (check and notify only; the UI links to the release page), `!app.isPackaged` → `dev` (state `unsupported`, updater untouched). `start()` runs the first check ~30 s after the window is ready and then every `settings.updates.checkIntervalHours` while `settings.updates.automatic` is on, a token exists and the policy has not set `updates.enabled: false`; `check()` is always allowed manually with a token; `download()` / `install()` (`quitAndInstall(false, true)`) are explicit; `autoDownload` = automatic ∧ can install in place; `autoInstallOnAppQuit` is on. Status transitions (`UpdateStatus` in `@rp/shared/updates`) are pushed on `updates:status`; `index.ts` shows a native "Restart now / Later" dialog when the update is downloaded and the window is visible, otherwise a notification (tray mode), and the tray menu has "Check for updates…".

## Preload (`src/preload/index.ts`)

Builds the `IpcApi` object generically: for each namespace/method a `ipcRenderer.invoke('<ns>:<method>', ...args)`; the `on*` subscriptions use `ipcRenderer.on(channel, (_, payload) => listener(payload))` returning an unsubscribe. Expose with `contextBridge.exposeInMainWorld('rp', api)`.

## Renderer (`src/renderer/`)

Three HTML entries: `index.html` (main UI), `media.html` (media overlay) and `prompt.html` (one pending question); a page picks by `window.rp.app.windowKind()` or by entry.

Main UI (React, one small store with `useSyncExternalStore` or plain context; no Redux):
- Layout: left sidebar (characters + sessions), centre chat, right/inline panels via routes: Chat, Packs, Settings, Action Log, SDK Reference (renders typings in `<pre>`).
- Chat: message list with streaming text (markdown rendering via a tiny safe renderer — use `marked` + `DOMPurify`? Keep deps small: use `marked` with `sanitize` via `dompurify`; both are on cdnjs but we bundle from npm), action cards (purpose, collapsible code, result/logs/error, duration), emote styling, status line, composer (Enter to send, Shift+Enter newline), abort button while a turn runs, "new session" for a character, scenario editor in session settings.
- Packs: list with capability toggles (pack-level grants), install button → `pickInstallSource`, uninstall confirm, README view, characters list with "Start chat".
- Settings: provider list (add/edit/remove; kind select; base URL; API key masked; model text + "fetch models" button; "test" button), default provider, maxActionRounds, contextTokenBudget, run limits, useToolCalling, userDisplayName, theme, mediaAlwaysOnTop. Senses: a "Live snapshot" card (its `auto-refresh` toggle is
  `settings.senses.liveSnapshotAutoRefresh`, so it survives leaving the tab), prompt inclusion, poll
  interval, idle threshold, calendar sources, watched directories. General → Debug: "Show model traffic" (`settings.debug.showModelTraffic`, default off).
- Model traffic drawer (`components/chat/ModelTrafficDrawer.tsx`): shown by a **Model traffic** header button (with a count badge) next to Events while `settings.debug.showModelTraffic` is on. Lists the session's `model-exchange` events newest first (time, kind/round, model, stop reason, tokens in↑ out↓, duration, error badge); expanding a row shows the request with collapsible System prompt (with the stable-prefix length), Messages (one block per message, content parts rendered by type: text, `name(input)` for tool_use, `→ result` for tool_result with an error badge, `[image mime, size]`), Tools JSON and the Response, plus Copy request/response JSON and Clear. The store keeps the last 40 exchanges per session in `SessionRuntime.exchanges` (memory only; cleared by `messages-cleared` and the Clear button); nothing is persisted.
- Settings → Browser (`components/settings/BrowserSection.tsx`, gets `settings` + `onPatch`): connection card (connected / browser / extension id, the bridge port field with a warning when the wanted port was taken), allowed extension ids with Remove buttons and an "Allow" field (refused ids of this run are listed), the "What characters may do" card (toggles `browser.allowBlocking` / `allowEval` / `allowHistory`, the, the "Home page" field → `browser.setHomePage`; managed badges per path), the "Active blocks" card (`browser.blocks()` on status changes and every 10 s while connected; **Clear all blocks** → `browser.clearBlocks()`), the policy card (computed extension id and update URL with Copy, **Install browser policy…** → confirm modal (mentions the home page and extra directories) → `browser.installPolicy()` with the installer output, **Remove policy**, the "Extra policy directories" textarea → `settings.browser.extraPolicyDirs`, the Windows/macOS Chrome and Flatpak notes) and the developers card (the unpacked extension path with Copy). Subscribes to `browser.onStatus`.
- Settings → Updates (`components/settings/UpdatesSection.tsx`): current version, status line with download progress, Check now / Download / Restart to update, the GitHub token field (save/remove, shows keyring vs file storage), the "check automatically" toggle (managed badge when the policy pins it), explanations for `deb` (notified only, link to the release page) and `dev` (unsupported); hidden token field when the policy disables updates.
- Unread marks: a message from a character in a session the user is not watching (`route !== 'chat'` or another session) increments `state.unread[sessionId]` — counted even when that transcript is not loaded, since that is exactly the case worth announcing. The sidebar shows a count per session and a total on the **Chat** entry; opening the session or returning to the chat clears it.
- Chat text size: `settings.chatZoom` (1 = 100%, clamped to `CHAT_ZOOM_MIN`..`CHAT_ZOOM_MAX` in `mergeSettings`) scales the transcript and the composer, and widens the reading column with them (`--chat-zoom` / `--chat-column` on `.chat`); the header and drawers keep the base size. Set from the chat header's `A− 100% A+` group, <kbd>Ctrl</kbd> `+`/`-`/`0` in the chat, or Settings → Appearance.
- Prompt fallback modals: `PermissionModal` / `UiPromptModal` render the same `components/prompt/` views inside the main window, and are reached only when no prompt window could be opened (`permissions.onRequest` / `ui.onPrompt`).
- Action log: table of audit entries with filter by session.

Prompt window (`prompt.html`): one question per window, opened by main, centred, `alwaysOnTop`, shown and focused on `ready-to-show`. The page pulls its question with `prompts.pending()` (keyed by the sender's webContents, so it cannot miss a push that arrived before React mounted) and answers on `permissions.respond` / `ui.respondPrompt`; main closes the window when the question settles (answered, timed out, or rejected on quit), and closing the window instead answers it with its fallback (deny / no answer). Closing the main window no longer cancels questions that have a window of their own.

Media window: full-viewport React page listening to `media.onCommand`; renders items (image with caption + fade; `<video>`/`<audio>` with autoplay, volume, loop; reports `ended`/`error` via `media.report`); `close`/`close-all` remove items; when no items remain the page reports `closed` for each and main hides the window. Click on an image closes it.

## Packaging

`electron-builder` config in `package.json` (`build` key) for win (nsis), mac (dmg), linux (AppImage, deb). `build.publish` points at the private GitHub repository (`0xbeef1eaf/llm-rp-code`, `private: true`) so `latest-linux.yml` is generated next to the AppImage; the release workflow still runs with `--publish never` and attaches the manifest itself. `pnpm build` must succeed in CI without signing. Do not run electron-builder in tests.

## Tests

- vitest for pure helpers: preload api builder (with a fake ipcRenderer), asset protocol path guard, range parsing, media window placement math, renderer store reducers, `PendingPrompts` (settle callback, filtered rejection), `promptIdOf`, notification urgency mapping.
- `pnpm build` (electron-vite build) must pass.
